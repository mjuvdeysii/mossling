# 摸索台灯 · 重新立项（v2）

状态：2026-10-26 立项。品牌与 IP 设定（[docs/IP.md](IP.md)）继续沿用；视觉、版式、插画、角色制作、引导与叙事全部按新项目重做，不在现有界面上修补。

## 1. 目标与验收

**目标**：做一款 iOS 原生应用，让大人愿意每天打开、和孩子一起玩，并被它打动；以 App Store 育儿类编辑推荐为标准。

**为什么重新立项**：现有版本由代码绘制的 2D 图形支撑。角色、插画和版式已经到了这条路线的上限，继续修补只会累积不一致。

**验收标准**（每一项都要有证据，不以自评代替）：

| 方面 | 标准 | 怎么验证 |
|---|---|---|
| 角色（IP） | 角色以三维模型制作，所有画面出自同一模型；至少 8 种表情与姿态；动画随时可中断，「减弱动态效果」时静止 | 渲染样张；5 位项目外的家长盲看，判断「像动画电影角色」的比例 |
| 插画 | 146 步每一步都能单独看懂谁在做什么、用什么 | 盲配测试：看图选步骤，正确率 ≥ 95%（上一版为 38/38 张封面） |
| 首次使用 | 新家长不看说明，能完成出生日期并打开第一件教具 | 5 位家长可用性测试，记录用时与卡点 |
| 首页 | 首屏只有一个主要动作（本周的架子）；从打开到开始玩 ≤ 10 秒 | 同上 |
| 成长地图 | 37 站一眼可读当前所在；任意月份两步内到达；滑动跟手、不错位 | 真机录屏、帧率记录 |
| 版式 | 设计系统统一：间距、字级、圆角、颜色、动效各有一套规范，所有页面只用这一套 | 逐页对照规范检查 |
| 数据 | 导出包含全部记录；可交给医生或 AI 助手阅读 | 单元测试 + 真机导出 |
| 性能与无障碍 | 滚动保持 60 帧；Xcode 无障碍审查在默认字号下零问题 | CI 报告 |

## 3. 已完成的第一步

- **数据**：导出与导入改为独立页面。完整备份包含全部设置、记录、测量和正在进行的计时；另有一份写给医生或 AI 助手阅读的文档。文件直接存入「文件」App，不经过系统文件选择器，因此不会触发联网询问。
- **角色**：三维制作路线已验证可行。Blender（Cycles 渲染器）可以在本项目环境中运行，`tools/ip3d.py` 已渲染出 Moss 与 Otto 的第一版样张（[白天](images/ip/pilot_day.jpg)、[夜里](images/ip/pilot_night.jpg)）。现在只是路线验证，还没达到电影水准，需要按 P1 继续雕刻造型、调整材质和灯光。

## 4. 需要你决策：插画路线

| 路线 | 能达到的水准 | 一致性 | 成本与风险 |
|---|---|---|---|
| A. 三维场景（与角色同一套 Blender 制作） | 黏土 / 玩具质感的动画电影风格 | 高：同一套模型、灯光和镜头 | 需要做出风格化的大人与孩子模型和动作；工作量最大，但完全可控、可重复 |
| B. AI 生成插画（通过已连接的 Canva） | 单张接近插画师水准 | 低：同一人物在不同画面里会走样 | 生成的文件无法从本项目环境直接取回，需要你手动下载约 330 张；每张都需人工挑选 |
| C. 委托插画师 | 真正的插画师水准 | 高 | 需要预算和周期；现有分镜（`tools/scenes.json`）可直接作为委托说明 |

建议：角色按 A 路线做（已在进行）。插画先用 A 路线做一个活动的 3 步样张，再与 C 路线的报价对比后决定。

## 5. 事实、推断与未知

- **事实**：
  - 应用在模拟器全部测试中没有发起网络连接（见 CI 生成的 `ios_network.txt`）。
  - 你观察到的联网询问出现在导出之后。
- **推断**：联网询问由系统文件选择器触发（它会访问 iCloud 云盘）。新的导出方式不再使用文件选择器，需要在真机上确认。
- **未知**：家长对新角色和新版式的真实反应，要在 P2 原型阶段用访谈验证。
